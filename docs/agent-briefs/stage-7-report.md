## Итог

Сквозной сценарий этапа 7 реализован и проходит: тестовая стратегия → HTTP-контракт БКС →
эмулятор → матчинг по REPLAY-данным → портфель → отчёт → сверка с эталонным бэктестом.

- [x] `FullCycleReplayIntegrationTest` — полный цикл за один прогон (24 торговых дня, SBER/GAZP/
      SiU6) через реальный HTTP: token → orders/sync → portfolio → limits → orders/search →
      trades/search → `/api/internal/reports`.
- [x] Детерминированный REPLAY-набор (`ReplayDataset`) и стратегия-генератор
      (`SmaCrossoverStrategy`, SMA 16/64, long-only); набор пишется в PostgreSQL до создания
      провайдера рыночных данных (`ReplaySeedSupport`).
- [x] Эталонный бэктест (`IdealBacktest`) — та же стратегия по ценам стакана без проскальзывания
      и комиссий; сверка `BacktestComparator` с порогом 30% по каждой сопоставимой метрике.
- [x] `LiveSmokeIntegrationTest` (тег `live`, по умолчанию пропускается без `ALGO_PACK_TOKEN`) —
      ручной smoke против реального AlgoPack/ISS.
- [x] Исправлен разрыв контракта: `POST /v1/trades/search` читал in-memory хранилище, которое
      никто не наполнял (с этапа 3 сделки лежат в `fills`), и всегда отдавал пустую страницу.
      Добавлен `JpaTradeServiceImpl` (выборка `fills` + заявка + инструмент), покрыт unit-тестами.
- [x] Документация: README («Прогон и сверка с бэктестом»), этот отчёт, статус в
      `docs/progress.md`.

| Параметр | Значение |

Набор синтетический, но детерминированный: это эквивалент записи сессии для воспроизводимого
прогона. Реальную запись можно подставить, заменив `ReplayDataset` (формат снапшотов и сидинг не
меняются).

## Покрытие контракта БКС

Сквозной прогон использует контракт целиком по пути стратегии; полная таблица эндпоинтов — в
отчёте этапа 2 (`stage-2-report.md`). В этапе 7 проверено через HTTP:

| Метод | Путь | Что проверено |
|---|---|---|
| POST | `/api/bks/.../token` | refresh → access (write-клиент) |
| POST | `/api/bks/v1/orders/sync` | MARKET-заявки стратегии, `X-Strategy-Id`, немедленное исполнение |
| POST | `/api/bks/v1/orders/search` | все заявки прогона (`totalRecords`) |
| POST | `/api/bks/v1/trades/search` | все сделки прогона (`totalRecords`) |
| GET | `/api/bks/v1/portfolio` | денежная позиция и depo-лимиты после прогона |
| GET | `/api/bks/v1/limits` | лимиты T0/депо/фьючерсы |
| POST | `/api/internal/reports` | отчёт, JSON/CSV, сверка с бэктестом |

## Допущения и отклонения

1. **Эталонный бэктест.** Внешнего эталона от владельца нет, поэтому эталон считается из того же
   набора: стратегия исполняется по ценам стакана без проскальзывания и комиссий. Это честная
   нижняя граница издержек: расхождение показывает суммарный эффект модели исполнения и тарифов,
   а не разницу стратегий. Замена на внешний эталон — через блок `backtest` запроса отчёта.
2. **Синтетический набор.** Реальная запись сессии/история AlgoPack в репозитории отсутствует;
   для воспроизводимости и независимости от сети используется детерминированный генератор.
3. **Фьючерсы.** Клиринг ВМ соответствует `MarginSettlementServiceImpl`: результат фьючерсной
   позиции уходит в кэш, рыночная стоимость в NAV не входит; фьючерсный лот закрывается внутри дня.
4. **Отдельная Gradle-задача `integrationTest` не вводилась** — `build.gradle` не менялся без
   разрешения владельца; `FullCycleReplayIntegrationTest` входит в `./gradlew test`.
5. **Нагрузка/стресс** — вне скоупа (TODO, если потребуется владельцу).
