# Бриф этапа 3: Домен + виртуальный портфель + персистентность

## Цель

Настоящий виртуальный портфель вместо заглушек этапа 2: кэш, позиции (акции + фьючерсы),
ГО и вариационная маржа, комиссии, ежедневный NAV; состояние переживает перезапуск
(PostgreSQL 18). Портфель БКС-эндпоинтов собирается из `PortfolioSnapshot` через adapter.

## Прочитать до начала

1. `AGENTS.md`, `ARCHITECTURE.md` — разделы 4, 8, 9 (ADR-5, ADR-10).
2. `docs/bcs-api/http/portfolio.md` + `limits.md` (встроенные схемы) — форма ответа.
3. Код этапа 2 (`bks/adapter`, `core/domain`) — расширять, не ломая контракт.

## Скоуп

- `core/portfolio`: `VirtualPortfolio` (кэш по валютам, позиции, блокировки), расчёт ГО
  (дефолт ~10%, настраивается per-instrument), вариационная маржа (ежедневная переоценка),
  маржа-проверка перед сделкой (не хватает обеспечения → отказ), NAV-снапшот по закрытию
  основной сессии (торговый календарь — упрощённо конфигом, полная интеграция — этап 4).
- `core/commission`: `CommissionCalculator` + тариф профиля (процент, минимальная комиссия,
  биржевой сбор фьючерсов); дефолт акций — 0.1%.
- `core/domain`: Position, Fill (цена, объём, комиссия отдельным полем), доведение Order.
- Корпоративные события: интерфейс `CorporateActionHandler` + заглушка `TODO(dividends/splits)`.
- `infra`: `repository/` (Spring Data JPA: orders, fills, positions, nav, accounts),
  `model/` (сущности БД), `mapper/` (MapStruct: сущность ↔ домен core), `services/`
  (оркестрация: сохранение/загрузка + вызов чистой логики core); миграции (Flyway —
  подтвердить выбор в отчёте); таблицы по черновику ARCHITECTURE.md §9.
- Подключение к `bks/adapter`: portfolio/limits собираются из реального снапшота.

## Обязательные тесты (≥80% покрытия логики портфеля)

- Покупка/продажа акций: кэш, позиция, средняя цена, комиссия.
- Фьючерс: ГО блокируется/освобождается, вариационная маржа начисляется, маржа-колл отказывает ордер.
- NAV: снапшот после переоценок; комиссионный сценарий частичного исполнения.
- Репозитории: @DataJpaTest (H2 не использовать — Testcontainers PostgreSQL 18; если недоступен
  в среде — согласовать fallback).
- Обновлённый `HealthCheckIntegrationTest`-сценарий: create order → fill(заглушка) → portfolio
  отражает позицию и кэш.
