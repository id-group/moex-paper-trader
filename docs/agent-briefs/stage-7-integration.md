# Бриф этапа 7: Сквозной интеграционный тест и сверка с бэктестом

## Цель

Полный цикл в одном прогоне: «стратегия» (тестовый генератор ордеров) → HTTP-контракт БКС →
эмулятор → матчинг по REPLAY-данным → портфель → отчёт; сверка метрик с эталонным бэктестом
(целевое расхождение < 30%). Финальная проверка Definition of Done всего проекта.

## Прочитать до начала

1. `AGENTS.md`, `docs/ARCHITECTURE.md` (весь), брифы этапов 2–6 (что должно быть готово).
2. `docs/bcs-api/restrictions.md` (если включаем эмуляцию rate-limit).

## Предусловия (входной контроль — проверить до старта)

- Этапы 2–6 завершены: `./gradlew clean build` зелёный; есть REPLAY-данные (запись сессии или
  история AlgoPack/ISS) по нескольким ликвидным инструментам (например SBER, GAZP, Si-фьючерс)
  минимум за N торговых дней (N ≥ 20 для метрик).
- Есть эталонный бэктест-результат для сравнения (метрики или ряд NAV от стратегии-генератора).
  Если эталона нет — запросить у владельца; без него критерий «<30%» непроверяем.

## Скоуп

- `src/test/java/ru/moex/papertrader/it/`:
  - `FullCycleReplayIntegrationTest`: поднимает приложение (REPLAY, Testcontainers PostgreSQL),
    прогоняет тестовую стратегию через реальный HTTP-контракт БКС (token → orders → fills →
    portfolio → report), формирует отчёт, сверяет с эталоном через `BacktestComparator`
    (assert: расхождение < 30% по каждой метрике: CAGR, Sharpe, MaxDD, WinRate...).
  - Стратегия-генератор: простая детерминированная (например, SMA-кроссовер или «покупай каждый
    N-й час») — только для прогона цикла, не продукт.
  - `LiveSmokeIntegrationTest` (тег `live`, по умолчанию выключен): против реального AlgoPack —
    quotes/order-book/create-cancel ордера; запуск только вручную с токеном в env.
- Нагрузка/стресс — вне скоупа (пометить TODO, если требуется владельцем).
- Документация: `README.md` — раздел «Прогон и сверка с бэктестом» (команды, где лежат отчёты,
  как интерпретировать); `docs/` — отчёт о расхождении последнего контрольного прогона.

## Definition of Done (проекта в целом)

1. Сервис стартует, `/health` отвечает.
2. Контракт БКС реализован (таблица покрытых эндпоинтов — в отчёте).
3. Ордер выставляется и исполняется (с проскальзыванием и комиссией).
4. Портфель корректно считает позиции, кэш, ГО, NAV (тесты этапов 3–5).
5. LIVE и REPLAY работают; RECORD пишет поток.
6. Модель проскальзывания — точно по спеке (тесты этапа 5).
7. Отчётность формируется, сравнение с бэктестом < 30% — **показать результат прогона**.
8. `./gradlew clean build` + все интеграционные тесты зелёные.
9. README/AGENTS/ARCHITECTURE актуальны; `docs/bcs-api/README.md` — статус схем «полные».

## Подводные камни

- Testcontainers требует Docker в среде выполнения; если недоступен — согласовать fallback
  (внешний PostgreSQL 18 из docker-compose.yml + отдельный профиль).
- Детерминизм прогона: фиксированные seed + Clock; никакие системные часы не должны протекать
  в матчинг (проверить ArchUnit-правилом этапа 4).
- Эталонный бэктест считается БЕЗ проскальзывания/комиссий эмулятора? Если так — расхождение
  30% должно это учитывать (метрики сравнивать честно, допущения записать в отчёт).
- Долгий прогон: держать тестовое окно компактным (секунды-минуты виртуального времени),
  полный прогон — отдельная Gradle-задача (`integrationTest` тег).
- Файлы — UTF-8 без BOM.
