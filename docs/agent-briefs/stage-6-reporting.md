# Бриф этапа 6: Отчётность и метрики

## Цель

По завершении торгового прогона (LIVE-сессия или REPLAY) формируется отчёт: кривая NAV,
метрики (CAGR, Sharpe, Sortino, Max Drawdown, Calmar, Win Rate), журнал сделок с
проскальзыванием и комиссиями, разбивка по стратегиям, сравнение с внешним бэктестом.

## Прочитать до начала

1. `AGENTS.md`, `docs/ARCHITECTURE.md` — раздел 10.
2. Код `core/reporting` (порт), `core/portfolio` (nav_daily), `core/execution` (fills),
   таблицы БД этапа 3.

## Скоуп

- `core/reporting`:
  - `MetricsCalculator` по ряду NAV (daily): CAGR (252 торговых дня/год), Sharpe (RF —
    конфигурируемый, дефолт — ключевая ставка ЦБ как константа конфига), Sortino (downside
    deviation), Max Drawdown, Calmar (CAGR/MaxDD), Win Rate (закрытые сделки, FIFO-сопоставление
    входов/выходов по позиции).
  - `TradeJournal`: журнал сделок — цена до/после проскальзывания, комиссия, strategyId,
    время (Clock); выгрузка JSON/CSV.
  - `StrategyBreakdown`: агрегаты по strategyId (PnL, количество сделок, win rate).
  - `BacktestComparator`: вход — метрики или ряд NAV внешнего бэктеста (JSON-контракт
    зафиксировать в `docs/`), выход — таблица отклонений (абс. и %), флаг PASS/FAIL по порогу 30%.
- Хранение: `backtest_results`, отчёты — таблицы БД + файловый экспорт (путь в конфиге).
- Доступ: внутренние (не БКС!) эндпоинты в корневом пакете — брокер-нейтральный контроллер
  отчётов `/api/internal/reports/**` (без токена брокера; решение согласовать в отчёте —
  контракт БКС не расширяем). Формат — JSON.
- strategyId: поле ордера из этапа 2 (заголовок `X-Strategy-Id` — допущение; если роутер
  передаёт иначе — согласовать с владельцем ДО реализации).

## Явно НЕ делать

- Графики/визуализацию (достаточно данных в JSON/CSV); сравнение нескольких прогонов между
  собой (только прогон ↔ эталонный бэктест); реал-тайм стриминг метрик.

## Обязательные тесты

- Метрики на синтетических рядах NAV с известным ответом (постоянный рост, пила, провал) —
  значения сверить с ручным расчётом/эталонной формулой в комментариях теста.
- FIFO win-rate на серии сделок (включая частичные).
- Journal: проскальзывание и комиссия раздельно; strategyId проброшен.
- Comparator: отклонение 25% → PASS, 35% → FAIL.
- Отчёт по завершении REPLAY-прогона (мини-сценарий в интеграционном тесте).

## Definition of Done

- `./gradlew clean build` зелёный; после прогона формируется отчёт (показать JSON в отчёте);
  формулы метрик задокументированы (Javadoc + таблица в `docs/` или README).

## Подводные камни

- Все расчёты — `BigDecimal`/`double` с явной политикой округления; годовая база — 252 дня.
- Sharpe/Sortino — на дневных доходностях ряда NAV (не внутридневных).
- Пустой ряд/нулевой NAV — определённое поведение (0 или NaN — зафиксировать).
- Файлы — UTF-8 без BOM.
