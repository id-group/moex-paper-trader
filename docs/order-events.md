# Журнал событий заявок (`order_events`)

Внутренний договор о колонке `quantity` по типам событий. Зафиксирован 2026-11-13
по итогам разбора прогона E2E-07 (`.planning/todos/pending/emulator-position-consistency.md`, P4):
раньше в одной колонке смешивались «размер события», «итог по заявке» и «остаток», что ломало
аудит и интерпретацию внешними потребителями.

Внешний контракт БКС Trade API (`docs/bcs-api/**`) события не использует: журнал внутренний,
читается из БД напрямую.

## Семантика `quantity`

| `event_type`       | `quantity`                                        |
|--------------------|---------------------------------------------------|
| `CREATED`          | объём заявки (`orders.quantity`)                  |
| `PARTIALLY_FILLED` | размер этого фишла                                |
| `FILLED`           | накопленный `orders.executed_quantity`            |
| `CANCELED`         | накопленный `orders.executed_quantity`            |
| `REJECTED`         | накопленный `orders.executed_quantity`            |
| `EXPIRED`          | накопленный `orders.executed_quantity`            |

Терминальное событие частично исполненной заявки поэтому показывает, сколько фактически
исполнено, а не какой остаток снят; для неисполненной заявки — `0`.

## Причина `EXPIRED`

У DAY-заявок причина включает таймстемп границы сессии из источника сессии:

```
Срок действия DAY-заявки истёк на границе сессии 2026-11-13T15:50:00Z
```

Это отличает «торговый день закончился» от «источники сессии разошлись» при разборе прогонов.
У GTD и при вызове без явной границы — прежний текст «Срок действия заявки истёк».

## Экспирация DAY

DAY-заявка живёт до конца торгового дня, под который создана: созданная до закрытия истекает
на границе закрытия, созданная после закрытия переносится на следующий торговый день и
истекает на его границе. Граница берётся из того же источника сессии
(`MarketDataProvider.tradingSession(...).closeAt()`), который разрешает исполнение, —
расхождения «календарь против рынка» нет. Если источник границу не сообщает (`closeAt == null`),
работает прежнее правило «сессия закрыта — срок истёк».
