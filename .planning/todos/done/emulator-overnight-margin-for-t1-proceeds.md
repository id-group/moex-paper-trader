# Разрешить внутридневное/ночное плечо для акции (BUY не отклонять из-за нехватки свободных средств)

Статус: done (2026-11-16, EM-01, коммит 8534f9e на ветке feature/08-stock-margin-buy)
Приорет: P1 (сейчас эмулятор блокирует ребаланс: покупка до зачисления T+1-выручки = REJECTED)
Репозиторий: moex-paper-trader, `infra/services/FillServiceImpl.java`, `core/portfolio/VirtualPortfolio.java`

# Контекст (E2E-прогон trading-service 2026-11-16)

Покупка BANEP отклонена: `Недостаточно свободных средств RUB: требуется 146851.71,
доступно 102711.71`. Причина: `checkStockAvailability` (`FillServiceImpl:323-343`) для
`Side.BUY` требует `availableCash ≥ цена×кол-во + комиссия`, где
`availableCash = cash − locked − otherOrderLocks`. Выручка от закрытия SNGS приходит по
акциям только на **следующий торговый день** (T+1), поэтому в момент ребаланса свободный кэш
меньше суммы покупок и брокер-эмулятор отказывает.

В реальности счёт с маржинальной торговлёй такую сделку пропускает (плечо на сутки):
отказы «недостаточно средств» для обеспечения-достаточного портфеля не происходит, позиция
временно уходит в дебет.

# Требуемое поведение

Для `Side.BUY` по акции не отклонять заявку из-за `available < required`, если портфель
достаточен по маржинальному критерию (например, стоимость удерживаемых бумаг покрывает
требование, либо включён флаг плеча). Разрешить `cash` уйти в отрицательный баланс в пределах
суточного плеча — по образцу уже существующей семантики фьючерсной ВМ
(`VirtualPortfolio.applyVariationMargin`: «кэш может уйти в минус»).

Ключевые ограничения:
- поведение включить конфигом (флаг профиля), `application-prod.yml` и `SecurityConfig`
  не трогать (запреты репо); дефолт оставить прежним, включение — только в local-профиле;
- `core` не должен начать зависеть от Spring; логику доступности держать в `infra`;
- не понижать компилятор/обходные пути по JDK.

# Тесты

`VirtualPortfolioTest`/`FillServiceImplTest`: BUY с нехваткой свободного кэша, но достаточным
обеспечением → заявка принята, кэш в минус в пределах лимита; при превышении лимита плеча →
прежний `InvalidOrderException`. Прогнать `./gradlew test --tests "*FillServiceImpl*"` и полный
`./gradlew build` (гейт репо отдельный от trading-service, JAVA_HOME=MOEX_JAVA25_HOME).

# Связано с trading-service

Реализовано как EM-01: флаг `emulator.portfolio.allow-stock-margin-buy` (дефолт false,
включён в application-local.yml), акционный BUY при нехватке свободного кэша идёт через
`VirtualPortfolio.buyOnMargin` — дебет в пределах балансовой стоимости удерживаемых бумаг,
кэш временно в минус до зачисления T+1-выручки; фьючерсы и продажи без позиции не затронуты.
Отказ при превышении обеспечения: «Недостаточно маржинального обеспечения RUB: дебет ...
не покрыт стоимостью удерживаемых бумаг ...».

Реактивный путь `buy-retry-on-insufficient-funds.md` (trading-service, TS-02) остаётся
страховкой на случай реального брокера — EM-01 убирает отказ только в эмуляторе.
