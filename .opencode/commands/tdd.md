---
description: TDD-цикл red → green → refactor для одной задачи ($ARGUMENTS)
---

Реализуй `$ARGUMENTS` по TDD: тесты пишутся до продакшн-кода, по одному поведению за раз.

Перед gradlew-командами выстави JDK 25: `$env:JAVA_HOME='C:\Users\id-gr\.jdks\liberica-full-25.0.4'`

Перед работой загрузи профильный skill из `AGENTS.md` §9, если задача в его области.

Для каждого поведения повторяй цикл:

1. **Red.** Напиши один тест (JUnit 5 + AssertJ; Mockito — только для границ, Spring Context не
   поднимать). Запусти только его: `./gradlew test --tests "<полное.имя.Класса>"`.
   Тест обязан упасть **по нужной причине** (отсутствует поведение, а не опечатка или ошибка
   компиляции). Если упал не по той причине — исправь тест, а не код.
2. **Green.** Напиши минимальный продакшн-код, достаточный для зелёного теста. Не добавляй
   функциональность сверх теста. Повтори тот же тест до зелёного.
3. **Refactor.** Убери дублирование и улучшь имена, не меняя поведение. Все тесты класса
   должны оставаться зелёными.

Правила, которые проверяются на каждом шаге:

- `core` — без Spring (ArchUnit в `./gradlew test`). Зависимости от `bks`/`infra` в `core` запрещены.
- Нельзя удалять или ослаблять существующие тесты (`AGENTS.md` §6).
- Комментарии в коде — на русском, кроме Javadoc.
- Сразу после зелёного шага запускай `./gradlew spotlessApply` и просматривай diff: форматтер не должен менять логику.

После завершения задачи:

1. Запусти `./gradlew test` целиком.
2. Запусти `/coverage` для проверки покрытия новых классов.
3. Сообщи: список тестов, что было красным на каждом шаге, итоговое покрытие.
4. Не коммить: коммит — только с подтверждения владельца (`/precommit`).
